# M0-08: Unknown map id silently becomes a random map

`src/core/match.js:22` reads
`if (mapId === 'random' || !eligible.includes(mapId)) mapId = rng.pick(...)`. A map id that does
not exist is treated the same as `random`, with no warning. Found during M0-02: the README line
`node test/trace.mjs phantom volt frosthollow 7 hard` used a map that does not exist (`frosthollow`),
and it still exited 0 with a winner on some random map, so nobody noticed the doc was wrong.

Keep the current behaviour for a **known** map that cannot seat the roster. bughunt and headless
rely on it: 8 players on a standard map fall back to an eligible battle map. Only an id missing
from `MAPS` should be an error.

## Acceptance

- [x] `new Match(..., { map: 'nosuchmap' }, seed)` throws, or records a warning event, for an id
      that is not in `MAPS` and is not `'random'`.
- [x] `node test/trace.mjs phantom volt nosuchmap 7 hard` exits non-zero with a message that lists
      the valid map ids.
- [x] A new test (for example `test/mapid.mjs`, or new assertions in `test/rules.mjs`, additions
      only) checks both of the above.
- [x] `node test/determinism.mjs 6` and the other gates stay green, so known-map and `random`
      behaviour is unchanged.
