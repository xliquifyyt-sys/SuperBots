# M0-05: bughunt 4+ reports Ricochet embedded in glacierfort step rect

Found during M0-02 (docs truth pass). `node test/bughunt.mjs 2` passes; `node test/bughunt.mjs 5`
(the README command) fails:

```
$ node test/bughunt.mjs 5
50 eight-bot matches checked
ISSUE x7: bot embedded in terrain — e.g. glacierfort T1 ricochet @36.2,16.4 depth 0.32
EXIT 1
```

## Repro

- Run index 3 of `test/bughunt.mjs` (mode `teams`, AI `easy`, 8 players, powerups `high`,
  airStrikes `normal`), seeds 9306 and 9308. The requested maps are standard maps that cannot
  seat 8 players, so `Match` picks an eligible battle map; both resolve to `glacierfort`.
- All 7 hits are the same spot across turns T1 to T5: Ricochet at 36.16,16.38, depth 0.32,
  against rect `{x:35.5, y:16.5, w:0.52, h:0.5, step:true}`.
- A standalone repro that mirrors bughunt's seeds and settings for runs 2 to 4 and prints each
  hit with its rect was used for M0-02. Re-create it under `test/` or scratch as needed.

## Hypothesis

`test/bughunt.mjs:46` checks the bot against every rect in `w.map.terrain`. `src/core/sim.js:151`
builds `physTerrain` without `step` rects ("stair steps stay in map.terrain for AI/spawn helpers
only"). So the sim never collides with this rect, and the invariant flags it. Decide which one it is:

1. **False positive.** The bot stands correctly on the physics ground (top y=17) and the step rect is
   only a helper. Then the invariant should skip `step` rects, or check against `physTerrain`.
2. **Real sink.** The rendered slope makes Ricochet look buried 0.3 to 0.4 units in the ramp. Then the
   sim or the map geometry needs the fix.
